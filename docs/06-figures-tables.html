6  Figures and tables

Everything so far has produced .rds files, which nobody reads. This chapter turns them into the two things a paper is actually made of. Move to examples/04-manuscript, which is the complete version of the simulation study.

6.1 The aggregating rule

Snakefile (excerpt)
rule figure1:
    input:
        script = "scripts/figure.R",
        setup = "scripts/setup.R",
        rds = expand("rds/{iterations}/sim/n{n}_rho{rho}_{method}.rds",
                     iterations = ITER,
                     n = [50, 100, 400],
                     rho = [0, 50, 80],
                     method = ["naive", "split"])
    output:
        "out/figure1.pdf"
    log:
        "logs/figure1.log"
    shell:
        "Rscript {input.script} --out {output} "
        "{input.rds} > {log} 2>&1"

The expand() sits in the rule that needs it. rule table1 next to it writes out the same call, because it happens to summarize the same grid — but it is free not to, and a supplementary figure covering only the large sample sizes would simply sweep less.

If multiple figures / tables share the same grid, they can certainly be defined once outside individual rules.

The R script receives all eighteen filenames as trailing arguments and stacks them:

scripts/figure.R (excerpt)
parsed <- parse_args(OptionParser(option_list = option_list),
                     positional_arguments = TRUE)
opt <- parsed$options
infiles <- parsed$args

res <- do.call(rbind, lapply(infiles, readRDS))

positional_arguments = TRUE tells optparse to accept bare arguments alongside the named flags, so the script can be called as

Rscript scripts/figure.R --out out/figure1.pdf rds/200/sim/*.rds

6.2 Figures

Nothing about the plotting code is Snakemake-specific — it is the ggsave() call you would write anyway:

scripts/figure.R (excerpt)
p <- ggplot(cov, aes(n, covered, color = method, group = method)) +
  geom_line() +
  geom_point() +
  geom_hline(yintercept = opt$level, linetype = 2) +
  facet_wrap(~rho) +
  scale_x_log10(breaks = sort(unique(cov$n))) +
  scale_color_manual(values = colors, labels = method_labels) +
  coord_cartesian(ylim = c(0.5, 1)) +
  labs(x = "n", y = sprintf("Coverage of %g%% CI", 100 * opt$level),
       color = "Method") +
  theme_minimal()

dir.create(dirname(opt$out), showWarnings = FALSE, recursive = TRUE)
ggsave(opt$out, p, width = 7, height = 3)
cat("wrote", opt$out, "\n")

Two conventions, though, that matter more inside a pipeline than outside one:

Keep the appearance in one place. The figure and the table both turn naive into something a reader sees, so the label and the color are decided once, in scripts/setup.R, which the scripts that draw things source:

scripts/setup.R (excerpt)
method_labels <- c(
  "naive" = "Naive",
  "split" = "Sample splitting"
)

colors <- c("naive" = "#d95f02", "split" = "#1b9e77")

rather than being buried in two separate ggplot calls that can drift apart.

NoteDeclare what a script sources — and split it so that hurts less

Snakemake has no way to know that figure.R reads another file, so scripts/setup.R is listed in the input: of the rules whose scripts source it. An undeclared dependency is the one failure mode Snakemake cannot warn you about: change a color and the figure that uses it stays quietly stale (Chapter 9). Declare it wherever changing it could change an output.

Which is an argument for keeping such files narrow. setup.R here holds only presentation — labels, colors, the plotting packages — and the simulation rules do not use setup.R. The simulation functions live somewhere else entirely, one per file:

examples/04-manuscript
R/gen_data.R          sourced by scripts/sim.R      -> an input to rule sim
R/select_forward.R
R/one_rep.R
scripts/setup.R          sourced by figure.R and table.R

so that the two kinds of change cost what they should. Editing a hex code plans four jobs — the figure, the table and the two PDFs — and leaves the grid alone. Editing R/one_rep.R plans all twenty-two, because the results really are wrong now. Had both lived in one setup.R, the color change would have rerun eighteen unnecessary simulations, since Snakemake cannot tell which half of a file you touched.

The R/ directory is the layout an R package uses. IowaBiostat/project-workflow is a talk and a small example project that goes into this further and is worth giving a read.
