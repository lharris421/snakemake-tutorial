4  One rule, many jobs

Look again at the Snakefile from Chapter 2 and notice how much of it is copied and pasted:

Snakefile (excerpt)
rule sim_naive:
    input:
        "sim.R"
    output:
        "rds/sim-naive.rds"
    shell:
        "Rscript sim.R naive {output}"

rule sim_split:
    input:
        "sim.R"
    output:
        "rds/sim-split.rds"
    shell:
        "Rscript sim.R split {output}"

Two rules, identical but for the word naive versus split. Now imagine the real version of this simulation: three sample sizes, three correlation levels, two methods. Eighteen rules, all the same, and one typo away from a figure that silently mixes up two scenarios.

Wildcards fix this. Move to examples/02-wildcards.

4.1 A wildcard is a hole in a filename

Snakefile (excerpt)
rule sim:
    input:
        "sim.R"
    output:
        "rds/sim/n{n}_rho{rho}_{method}.rds"
    shell:
        "Rscript sim.R "
        "--n {wildcards.n} "
        "--rho {wildcards.rho} "
        "--method {wildcards.method} "
        "--out {output}"

The output is no longer a filename; it is a pattern. The parts in braces are wildcards, and they work backwards: when something asks for rds/sim/n400_rho80_split.rds, Snakemake matches that name against the pattern, concludes that n is 400, rho is 80 and method is split, and substitutes those values into the command wherever {wildcards.…} appears.

This is the mental adjustment that makes Snakemake click. You do not tell it to run the simulation eighteen times. You tell it what a result file is called as a function of its parameters, and then you ask for the files you want.

ImportantWildcards match anything, including nonsense

A wildcard is a regular expression, .+ by default. Nothing in the rule above says method has to be naive or split, so asking for rds/sim/n50_rho0_bayes.rds produces a perfectly valid job that runs sim.R --method bayes and fails inside R. Chapter 5 shows how to constrain wildcards, and Chapter 9 shows what that failure looks like.

4.2 Naming files so this works

Wildcards make your file-naming scheme part of the pipeline’s logic, which is worth two minutes of thought up front:

  • Put every parameter that changes into the name. If two runs differ in anything, their outputs must differ in name, or one will overwrite the other and Snakemake will believe both are up to date.
  • Use a separator that cannot appear in a value. These examples use _ between fields and stick to digits and lowercase letters within a field.

The scheme here is n{n}_rho{rho}_{method}.rds, with rho as a percentage so that it stays an integer — rho50 rather than rho0.5, because a decimal point in a filename is an invitation to trouble.

4.3 expand()

Something still has to say which eighteen files we want. That is expand():

Snakefile (excerpt)
N = [50, 100, 400]
RHO = [0, 50, 80]
METHODS = ["naive", "split"]
Snakefile (excerpt)
rule figure:
    input:
        script = "figure.R",
        rds = expand("rds/sim/n{n}_rho{rho}_{method}.rds",
                     n=N, rho=RHO, method=METHODS)
    output:
        "out/figure1.pdf"
    shell:
        "Rscript {input.script} {output} {input.rds}"

expand() takes a pattern and some lists and returns every combination of them, so

expand("rds/sim/n{n}_rho{rho}_{method}.rds", n=N, rho=RHO, method=METHODS)

returns a list of 3 × 3 × 2 = 18 filenames. Those are the inputs of rule figure, which is what causes all eighteen simulations to run.

NoteThe Python you need

N = [50, 100, 400] is a list, the same idea as c(50, 100, 400) in R. That is essentially the entire Python vocabulary required to use Snakemake: lists, strings in quotes, and the occasional dictionary in Chapter 5.

The expand() sits inside the rule that needs it, which is where a grid usually belongs: another rule is free to sweep a different one, and a supplementary figure covering only the large sample sizes would simply expand over fewer. When several rules genuinely share a grid, define it once above them and use the variable in each.

The script on the other end receives all eighteen filenames as arguments and stacks them:

figure.R (excerpt)
args <- commandArgs(trailingOnly = TRUE)
outfile <- args[1]
infiles <- args[-1]

res <- do.call(rbind, lapply(infiles, readRDS))

Note that expand() fills wildcards in, and {wildcards.n} reads them back out. These are opposite operations, and it is worth being clear about which one you are doing: expand() appears in the rule that consumes many files, and {wildcards.…} in the rule that produces one.

The DAG has changed shape: one rule now stands for eighteen independent jobs, all of which must finish before the figure runs.

That is the shape snakemake --dag reports, abbreviated in the middle: one node per job, each sim node carrying the wildcard values it was matched with. snakemake --rulegraph collapses all eighteen back into a single sim box, which is the view you want once a workflow has more than a few rules (Chapter 9).

4.5 Building one cell of the grid

Because the output is a pattern, you can ask for any file it can match, whether or not anything else wants it:

$ snakemake --cores 1 rds/sim/n50_rho0_naive.rds
Using shell: /bin/bash
Provided cores: 1 (use --cores to define parallelism)
Rules claiming more threads will be scaled down.
Job stats:
job      count
-----  -------
sim          1
total        1

Select jobs to execute...
Execute 1 jobs...

localrule sim:
    input: sim.R
    output: rds/sim/n50_rho0_naive.rds
    jobid: 0
    reason: Missing output files: rds/sim/n50_rho0_naive.rds
    wildcards: n=50, rho=0, method=naive
    resources: tmpdir=/var/folders/gz/hbrw64n97wb0vy5prhnxst400000gp/T
wrote rds/sim/n50_rho0_naive.rds -- coverage: 0.823 

Finished jobid: 0 (Rule: sim)
1 of 1 steps (100%) done

This is how you develop. Rather than running the whole grid to find out whether your new method works, ask for one small scenario, look at it, and only then let the rest go.

This is also extremely powerful, because now if you want a certain simulation… you just ahve to ask for it rather than edit an R file and run it.

4.6 Try it

  1. Add 1000 to N and run snakemake -n. How many jobs? Which ones are new?
  2. Ask for rds/sim/n77_rho33_naive.rds. It works — explain why.
  3. Ask for rds/sim/n50_rho0_bayes.rds and watch it fail. Where does the error come from, and how would you have preferred to find out?
